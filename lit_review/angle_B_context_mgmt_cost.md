# Angle B: agent context management, prompt/KV caching economics, and cost-aware agent evaluation

Compiled 2026-10-10 for "Cheap but Confused? The accuracy cost of cache-optimized context layouts in LLM agents".
Extends `00_preemption_sweep_2026-10-10.md` (sections 2, 3, 5); none of the ids below appears there.
Every id was verified on 2026-10-10 against the arXiv API (`export.arxiv.org/api/query?id_list=`) or the
`arxiv.org/abs/<id>` page; the verification route is recorded per row in `angle_B.csv`.

## Framing

The sweep established that the context-management literature measures accuracy and token count but not
cached cost, and that the caching literature measures cost and latency but not accuracy. This angle asks
what has filled that gap from six adjacent directions. Three things stand out. First, the compaction
literature of late 2025 and 2026 (Context-Folding, AgentFold, ACON, ReSum, StateComp, TRACE, the
DiscoveryBench condenser study) has become careful about *when* history may be replaced and about the
side effects of replacing it (instability, weakened recency, more retrieval calls), but it still reports
raw token counts, never cache-read tokens or billed USD; a method that cuts tokens 40% while breaking the
prefix can cost more at 0.1x read pricing, and nobody in this set checks. Second, production trace
studies now exist: the GitHub Copilot study (2608.00101) reports roughly 90% KV-cache hit rate within a
turn, about 55% at turn boundaries, and "drastic" invalidation after model switches or context
compaction; TraceLab (2606.30560) and the IISWC characterisation (2605.26297) agree that agent serving
is prefix-reuse-dominated once caching works. These give external anchors for the hit fractions we will
log per layout, and they confirm that compaction (our L3) is the main cache-breaking event in the wild.
Third, cost-controlled evaluation has matured past AI Agents That Matter: HAL (2510.11977) and
Cost-of-Pass (2504.13359, "expected monetary cost of a correct solution") give us the exact metric name
and reporting convention for USD per correct task, and the scaffold papers (2607.22585, 2607.06906,
2608.08654) show that harness-level choices move cost per task by 40x while pass rate barely moves,
which is the class of effect we are isolating one factor of. On tools, the "mask vs remove" question
remains unmeasured, but the catalog-size effect is now well documented (LongFuncEval 2505.10570,
RAG-MCP 2505.03275, 2605.24660), which supports keeping the tool block fixed and small in all layouts
so that tool-count effects do not confound layout effects. Position-independent caching added three
2026 systems (COMB, KVBoost, C2KV) that again report accuracy loss from naive non-prefix reuse and fix
it with training or recompute; none evaluates the API-level discipline.

## What this angle implies for D3 (hybrid recitation) and D5 (price threshold)

For D3, the compaction literature now contains three distinct designs that an L4 recitation block sits
between: trained folding/state blocks that replace history (AgentFold, Context-Folding, InfiAgent),
learned "safe to replace" labels (StateComp), and the empirical warnings that replacing history
weakens recency and destabilises runs (TRACE 2608.06503, FoldAct 2512.22733). L4 keeps history intact
and only appends a current-state restatement, so if D3 holds it is the first content-matched evidence
that the benefit these methods attribute to compression comes largely from *restating current state
near the question*, not from deleting the past. If D3 fails, StateComp and TRACE offer the likely
explanation: a restatement that does not mark superseded values explicitly does nothing against
stale-value errors. The audit codes should therefore distinguish "recitation present but ignored" from
"recitation wrong".

For D5, the external anchors are now concrete. Production hit rates of ~90% within a turn and ~55% at
turn boundaries (2608.00101) bound what L1 can achieve and show that compaction (L3) is the dominant
real-world invalidation event; the cost-controlled evaluation papers (HAL, Cost-of-Pass, Harness
Effect, Long-Horizon-Terminal-Bench) all price tokens at list rates with no cache split, so their
cost-per-task numbers are biased against append-only layouts by exactly the cache-read discount. Our
threshold estimate should be presented as the correction to that convention: report USD per correct
task from billed `usage.cost`, then recompute it under counterfactual cache-read multipliers (0.025x,
0.1x, 0.25x, 0.5x, 1.0x) to locate where L3's per-call savings stop paying for its cache misses, and
compare the result against the condenser study's un-cached finding that LLM summaries already cost
24-94% more tokens than they save (2605.18854). The scaffold papers' 40x spread in tokens per solved
task (2607.22585) is the scale against which a layout-only effect should be framed as one isolated,
measurable lever.
