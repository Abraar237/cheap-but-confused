Cheap but Confused? The accuracy cost of cache-optimized context layouts in LLM agents

Holding information content fixed, does the cache-friendly append-only layout cost accuracy, and does the cache discount pay for it? · FROZEN 2026-10-10 · Mohammed Abraar, Vizuara Research
Headline questions. Q1: with content held fixed, does the cache-optimal append-only layout (L1) lose task accuracy relative to a relevance-reordered layout (L2) and to a stable-prefix hybrid that appends a recitation block (L4)? Q2: does keeping superseded tool results in context cause stale-value errors, and does oracle pruning (L3, which changes content and breaks the prefix) remove them? Q3: what is the cost per correct task of each layout under provider-reported cache hits and billed USD, and at what cache-read price does the cheapest layout per call stop being the cheapest per correct answer? Q4: does the answer depend on the model family and on trajectory length?

Pre-registered directions (recorded 2026-10-10, before any model call)

IdDirection
D1L1 accuracy is below L3 on stale-trap steps, the gap grows with trajectory length, and there is no comparable gap on neutral steps.
D2L2 does not significantly beat L1 (reordering no better than shuffling, as in RAG), while its cache-read fraction falls below 20% and its USD per task rises by at least 3x on 0.1x-read pricing; L2 is dominated on the frontier.
D3L4 recovers at least 50% of the L1-to-L3 accuracy gap while keeping at least 80% of L1's cache-read fraction, and sits on or inside the frontier for every model.
D4The L1-vs-L3 gap shrinks with model capability; the confusion cost is largest for the cheapest models, where caching saves the least absolute money.
D5Per correct task, L3 is cheapest when cache reads are expensive and L1/L4 become cheapest below a cache-read price threshold; the threshold is reported per model and compared with the published break-evens.

The StaleTrap testbed (T1, primary)

ElementChoice
Environment3 stateful domains (inventory, calendar, ticketing) + a never-required messaging/HR domain; 39 JSON tools; deterministic local executor; every result declares which (record, field) values it states.
PrefixSystem prompt + tool declarations = 5,102 tokens on Google's tokenizer, above every provider's implicit-cache minimum; byte-identical across layouts.
Tasks144 = 3 domains x 3 templates x 4 lengths (6/12/18/30 tool calls) x 2 distractor levels x 2 seeds; two phrasings each; 720 question steps (360 stale-trap, 360 neutral).
Trap threadsread a field, update it 1 to 3 times, ask for the current value at a no-tool step. Two kinds: own (the agent's write returns the new value) and external (someone else changes the record; the new value appears only as a row inside an unrelated listing the agent was asked for). Every stale value differs from the answer by construction (360/360 checked).
Neutral threadsread once, ask later; nothing in context competes.
Distractorslow: compact unrelated reads/writes. high: verbose listings, near-miss identifiers, writes to other fields of thread records. Same call count, different volume and pressure.
Scoringexact match on canonicalised answer vs the executor's live state; stale_present marks whether the trap materialised; action-step fidelity logged; episode success = all questions correct.

Layouts (content identical for L1, L2, L4)

IdLayoutPrefixRule
L1cache-optimalstablesystem + tools first, every block verbatim in arrival order, newest last; tools masked by tool_choice, never removed
L2relevance-reorderedrewritten every turnsame blocks, stable-sorted by record identifiers shared with the current turn, most relevant last
L3oracle-prunedbreaks at first editevery value a later result restates is redacted in place (<superseded at step k>); whole result replaced when all its values are superseded; transcript-derived, schema-level rule

Analysis

  • Unit = task. Paired contrasts L1-L2, L1-L3, L4-L1, L4-L3, L2-L3 on trap accuracy, neutral accuracy, success, billed USD, cache-read fraction: sign-flip permutation (20k), task bootstrap CIs (10k), paired dz, template-cluster exact sign-flip as robustness.
  • Interactions by label permutation: gap x length, gap x distractor, trap vs neutral, gap x family.
  • D3 recovery fraction (L4-L1)/(L3-L1) with bootstrap CI; D5 USD per correct task from billed cost and under counterfactual cache-read multipliers 0 to 1x.
  • Benjamini-Hochberg over the full family; bold survivors only. Hand audit of at least 30 wrong answers, shipped.
